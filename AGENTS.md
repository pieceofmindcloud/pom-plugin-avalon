# Project agent memory

- POM plugin `avalon` (`pom-plugin-avalon`), created from the POM `creating-pom-plugins` skill. The contract lives in the POM repository: `docs/subsystems/plugins-ui.md` and `docs/subsystems/enterprise-licensing.md`.
- `src/abi.rs` is the C ABI v1 boundary (entry `pom_avalon_plugin_v1` in `src/lib.rs`); keep domain code out of it. `src/lib.rs` dispatches `host.*`, `ui.*`, `rpc.*` and `peer.*` operations; `src/context.rs` reads `host.configure`.
- `query` must answer at once: the node waits 3 s and one slow call blocks every other. Slow work (downloads, child processes, indexing) runs on a thread the plugin owns.
- The plugin host speaks IPC over its own stdin/stdout: any child process gets `Stdio::null()` for stdin and a log file for its output, never the inherited streams.
- Secrets (`gateway.api_key`, `host_api.token`, upstream tokens) never appear in `rpc.*` replies, `host.services`, logs or screens.
- `ui/manifest.json` is the `pom-plugin-ui/v1` screen contract; `release/manifest.json` is the release contract (ABI, feature set, preferences). `ui/src/host/runtime.ts` and `ui/src/host/ready.ts` are the only files that read `__POM_HOST__`. CSS classes use the `pb-` prefix, which `ui/build.mjs` renames to the plugin code.
- `scripts/build-ui.sh` generates the ignored `ui/dist/`; `scripts/package.sh` builds an installable artifact and the per-platform GitHub manifest. The POM local rebuild runs `development.rebuild` with the source read-only (`scripts/dev-ui.sh` writes to `POM_PLUGIN_OUT_DIR`).
- The engine is the Avalon fork of llama.cpp (one model family, `qwen4exp` / Qwen3.8-Flash-Next, experts in RAM with a GPU expert cache). It runs as `llama-server` under the plugin: `src/launch.rs` maps `engine.load` to its flags (loopback, `--jinja`, KV type from `kv`, Avalon's `-b/-ub 9536`, MTP from the model folder's `MTP/*.gguf` with `--spec-type draft-mtp`), CUDA cards through `CUDA_VISIBLE_DEVICES`, AMD through `HIP_VISIBLE_DEVICES` from `gpu_devices`. `engine.lock` pins the fork's `pom` branch; its feature branches (`feature/external-tensor-data`, `feature/hidden-state-input`, cherry-picks from the POM's llama.cpp fork, and `feature/stage-link`) are neutral and merged into `pom`.
- Sessions (`src/sessions.rs`): one llama-server slot per conversation (`id_slot`), restored from `<key>.full` when it starts the prompt and saved after each turn; the POM moves `full`/`full_ids` between machines (no delta). The prefill/decode split rides on them. Off on a stage of a split model.
- Stages (`launch::stage_role`): `link: {}` or a slice that does not hold the last layer runs `bin/stage-server --stage-serve` and answers `engine.link`; the last stage runs `bin/server --stage-prev` through the node's relay. `docs/stages-design.md` has the limits.
- `scripts/build-runtime.sh` builds `llama-server` statically into `build/runtime` (CUDA or CPU; `CUDA_ARCHITECTURES`, `AVALON_PORTABLE=1` for a release); `--hip` builds the AMD runtime into `build/runtime-hip` inside ROCm's image (`docker/runtime-hip.Dockerfile`, or on the host with `/opt/rocm`; `AMDGPU_TARGETS`, default `gfx1100;gfx1101;gfx1102;gfx1201`), copying the ROCm libraries the node lacks into its `lib/`. `launch::wants_hip` picks `runtime-hip` when the node gives no NVIDIA card and has an AMD one. Build from a worktree of the fork, never the checkout being edited.
- RAM: Avalon copies every expert to anonymous RAM when they fit (else a smaller arena); stages that share a machine each measure the free RAM alone, so the `expert_ram_gb` setting caps it (`GGML_CUDA_MOE_ARENA_MB`).
- AMD: Avalon's 1 MiB `HSA_SCRATCH_SINGLE_LIMIT` makes ROCr release each dispatch's scratch, which hung an RX 7800 XT (gfx1101); a HIP launch sets `HSA_NO_SCRATCH_RECLAIM=1` (proposed upstream, freriadoc/Avalon#60). `flash_attn` (default on) is only a fallback switch; off keeps the V cache f16. A slot that takes another conversation is erased first.
- Releases: `.github/workflows/release.yml` (manual, Linux x86_64) builds the CUDA and HIP runtimes portable from `engine.lock`, and `scripts/package.sh --runtime/--runtime-hip` attaches them and compiles their URL, SHA-256 and size into the library; `src/runtime.rs` downloads the one the cards need on a machine's first load (`curl`, `sha256sum`, `tar` of the node image).
- Verify with `scripts/build-ui.sh && POM_UI_REQUIRE_DIST=1 cargo test --locked && cargo fmt --check && cargo clippy --locked --all-targets -- -D warnings && tests/test_ci_plan.sh`.
